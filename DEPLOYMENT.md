# Deploying Smart Darshan

The whole project runs on free plans:

| Part | Where | What it runs |
|---|---|---|
| Database | **MongoDB Atlas** (free M0 cluster) | MongoDB |
| `smart-darshan` | **Render** web service (Node) | Express API + Socket.IO, and it serves the built React app |
| `smart-darshan-ml` | **Render** web service (Python) | Flask prediction service under gunicorn |

The repository already contains everything Render needs (`render.yaml`). You only create the two accounts and paste in a few values. Allow about 30 minutes the first time.

---

## Step 1 – Create the database (MongoDB Atlas)

1. Sign up at <https://www.mongodb.com/cloud/atlas/register> and create a **free M0** cluster. Pick a region near your users (e.g. Mumbai `ap-south-1`).
2. **Database Access** (under *Security*) **→ Add New Database User.** Choose *Password* authentication, a username (e.g. `smartdarshan`) and an auto-generated password. Give it *Read and write to any database*. Keep the password somewhere safe.
3. **Network Access** (under *Security*) **→ Add IP Address → Allow access from anywhere** (`0.0.0.0/0`). Render's servers do not have fixed IP addresses, so this is required. Only the username and password protect the database, so keep them secret.
4. On your cluster click **Connect → Drivers → Node.js** and copy the connection string. It looks like:

   ```
   mongodb+srv://<username>:<db_password>@<your-cluster-address>/?retryWrites=true&w=majority&appName=Cluster0
   ```

   Replace `<db_password>` with the real password. **Never put this string in any file in the repository**; it only goes into Render and the `db:copy` command. If the password contains `@ : / ? # [ ] %`, URL-encode those characters (for example `@` becomes `%40`).

You don't need to add a database name. The app uses `smart_darshan` automatically when the string has none.

## Step 2 – Put data in it (choose one)

**A. Copy your local data (recommended).** This keeps every account, temple, booking and the 90 days of history, and everyone can log in with the same passwords. On your PC:

```bash
npm run dev:db
```

Leave that running and, in a second terminal:

```bash
npm run db:copy -- "<your Atlas connection string>"
```

It prints each collection as it copies. The local database is only read, never changed. If Atlas already has data, the script stops; add `--replace` to overwrite it.

**B. Start with fresh demo data.** Skip the copy. In Step 3 set `AUTO_SEED` to `true` and `DEMO_PASSWORD` to a password of your choice (8+ characters). On its first start the API loads the three demo temples, and **every demo account uses `DEMO_PASSWORD`**, not the public passwords in the README.

> Either way, the demo accounts (`superadmin@smartdarshan.in` and the others) exist on the live site. With option A they keep the passwords printed in the README. Change at least the superadmin and admin passwords after deploying: log in and open `/profile`.

## Step 3 – Deploy on Render

1. Sign up at <https://render.com> with your GitHub account (Maddy3006) and allow access to the `Smart_Darshan-FSD` repository.
2. **New → Blueprint**, pick the repository and branch `main`. Render reads `render.yaml` and shows the two services.
3. Fill in the values it asks for:

   | Key | Value |
   |---|---|
   | `MONGO_URI` | the Atlas connection string from Step 1 |
   | `ML_SERVICE_URL` | `https://smart-darshan-ml.onrender.com` (the prediction service's address; check it in Step 4) |
   | `DEMO_PASSWORD` | only for option B, otherwise leave empty |
   | `TWILIO_*` | leave empty unless you have a Twilio account (SMS then goes to the log) |

   `JWT_SECRET` and `ML_API_KEY` are generated by Render automatically. The API and the prediction service share the same `ML_API_KEY`, so nobody else can use the prediction service.
4. Click **Apply**. The first build takes 5–10 minutes. When both services are *Live*, open the **smart-darshan-ml** service and compare its URL with the `ML_SERVICE_URL` you entered. If Render added a suffix (e.g. `smart-darshan-ml-x7k2.onrender.com`), go to **smart-darshan → Environment**, correct `ML_SERVICE_URL` and save. The service redeploys by itself.
5. For option B, set `AUTO_SEED` back to `false` once the site works, so a wiped database is never refilled automatically.

## Step 4 – Check it works

Open `https://smart-darshan.onrender.com/api/health` (use your service's URL). You should see:

```json
{ "ok": true, "db": "connected", "ml": { "online": true, ... }, "sms": "mock" }
```

Then open `https://smart-darshan.onrender.com`, log in, and check:

- **Analytics & forecast** shows "Prediction service online". The first time, the models are trained automatically within about a minute, and forecasts show historical averages until then.
- The **Live** dot on the dashboard is green.
- The gate scanner camera works on a phone, because Render serves the site over HTTPS.

Every `git push` to `main` redeploys automatically (the prediction service only when something in `ml-service/` changed).

## Things to know about the free plans

- **Services sleep after 15 minutes without visitors.** The next visit takes about a minute to wake them. Open the site a few minutes before a demo or review. While asleep, the scheduled jobs (expiring missed tokens, creating new slots, nightly retraining) do not run. They catch up when it wakes, because slots are created on every start.
- **The prediction service forgets its models on every restart** (free instances have no permanent disk). The API notices and retrains them automatically from the footfall history in Atlas. Nothing to do.
- Render's free plan has a monthly limit on running hours shared by your services. Because free services sleep when idle, a project demo normally stays within it.
- Atlas M0 gives 512 MB of storage, far more than this project needs.

## Environment variables (reference)

**smart-darshan (Node API)**

| Variable | Required | Meaning |
|---|---|---|
| `NODE_ENV` | yes | `production` |
| `MONGO_URI` | yes | MongoDB connection string. The API refuses to start in production without it. |
| `JWT_SECRET` | yes | Long random string. The API refuses to start in production without it. |
| `ML_SERVICE_URL` | yes | Public URL of the prediction service |
| `ML_API_KEY` | recommended | Shared secret, must equal the prediction service's `ML_API_KEY` |
| `CLIENT_URL` | no | Site URL used in SMS links and CORS. Defaults to Render's own URL (`RENDER_EXTERNAL_URL`). Comma-separate several. |
| `AUTO_SEED` | no | `true` loads demo data into an empty database (default `false` in production) |
| `DEMO_PASSWORD` | with `AUTO_SEED=true` | Password for every seeded demo account |
| `SERVE_CLIENT` | no | Default `true` in production: the API also serves the React app. Set `false` if you host the frontend elsewhere. |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER`, `TWILIO_WEBHOOK_URL` | no | Real SMS through Twilio |

**smart-darshan-ml (Python)**

| Variable | Meaning |
|---|---|
| `ML_API_KEY` | When set, every endpoint except `/health` needs the header `X-Api-Key` |
| `PORT` | Set by the host. Locally the service uses 8000. |
| `MODELS_DIR` | Where trained models are saved (default `ml-service/models`) |

## Other hosts

Nothing in the code is Render-specific.

- **API:** any Node 20.19+ host with WebSockets (Railway, Fly.io, a VPS). Build with `npm ci --prefix server --omit=dev && npm ci --prefix client --include=dev && npm run build --prefix client`, start with `npm start --prefix server`, and set the variables above.
- **Prediction service:** any Python 3.10+ host. Run `pip install -r ml-service/requirements.txt`, then from `ml-service/` run `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120`.
- **Frontend on a separate host** (Vercel, Netlify): build `client/` with `VITE_API_URL=https://your-api-url`. Add a rewrite so every path serves `index.html`. On the API set `SERVE_CLIENT=false` and `CLIENT_URL=https://your-frontend-url`.
